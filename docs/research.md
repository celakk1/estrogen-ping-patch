# Source verification and feasibility research

Research checked on 2026-10-31. These references establish design constraints; they do not prove improvements on a particular Windows client or adapter. Exact crate/npm resolutions are recorded in lockfiles.

- [Tauri Windows prerequisites](https://v2.tauri.app/start/prerequisites/): MSVC development tools and WebView2 are required. The launcher checks them before starting compilation.
- [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/): NSIS supports Windows distribution. The configured build is per-user and does not elevate the development launcher.
- [NSIS command-line usage](https://nsis.sourceforge.io/Docs/Chapter3.html): `/D=` and `_?=` must be last and unquoted even for paths with spaces. The installer smoke test uses `_?=` so waiting for the uninstaller covers its full lifecycle rather than only its temporary-copy bootstrap.
- [Tauri process model and external binaries](https://v2.tauri.app/develop/sidecar/): lifecycle ownership must be explicit. This build uses a local logical service; the privileged service remains a separate required component.
- [Microsoft named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights): default descriptors may grant read access to Everyone/anonymous. A privileged protocol requires an explicit security descriptor and verified caller identity.
- [Get-NetAdapter](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapter): supports read-only adapter discovery and hidden/virtual adapter enumeration. The embedded script uses supported NetAdapter and NetTCPIP cmdlets.
- [Get-NetIPConfiguration](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-netipconfiguration): documents IP configuration discovery; default output alone excludes some virtual/disconnected interfaces, so discovery collects adapters, IP interfaces, routes, and resolvers separately.
- [Microsoft adapter performance tuning](https://learn.microsoft.com/en-us/windows-server/networking/technologies/network-subsystem/net-sub-performance-tuning-nics): trade-offs depend on hardware and workload. This is Windows Server guidance and is not treated as proof that a setting benefits a Windows 10/11 client.
- [RFC 6349](https://www.rfc-editor.org/rfc/rfc6349.html): managed-network TCP throughput methodology. TCP connection establishment alone is not a substitute for throughput or loaded responsiveness.
- [MCP stdio transport](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports): newline-delimited UTF-8 JSON-RPC; stdout must contain protocol messages only. Implemented protocol version is explicitly pinned to 2025-06-18, rather than claiming every newer version is supported.
- [Cloudflare resolver addresses](https://developers.cloudflare.com/1.1.1.1/ip-addresses/) and [Google Public DNS addresses](https://developers.google.com/speed/public-dns/docs/using): identify independent public DNS destinations used as editable TCP port-53 defaults. These probes do not change DNS settings or claim to measure DNS resolution.

## Research gates still open

Verify official provider APIs, traffic policies, privacy terms, supported discovery, and redistribution licenses before implementing NDT7, Cloudflare throughput infrastructure, or optional Ookla/iperf3 adapters. No undocumented website endpoint is used as a speed-test API. Verify Windows 10/11 client API compatibility and driver behavior in a test lab before enabling any candidate setter. Verify supported inference APIs, credential protection, and MCP proposal validation before enabling paid or local inference.

## Backup and DNS restoration constraints

- [Get-NetAdapterAdvancedProperty](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapteradvancedproperty) exposes driver registry keywords and values; [Get-NetTCPSetting](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpsetting) exposes TCP template settings. Snapshot capture reads these supported interfaces and records unavailable sections.
- [Set-DnsClientServerAddress](https://learn.microsoft.com/en-us/powershell/module/dnsclient/set-dnsclientserveraddress) documents that a static DNS list overrides DHCP, while `-ResetServerAddresses` returns to DHCP DNS. IP DHCP status alone therefore cannot identify DNS configuration origin. A restore path must preserve that distinction instead of writing previously resolved DHCP addresses as a static list.
- [GetInterfaceDnsSettings](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getinterfacednssettings) now supplies the native version-one snapshot section, with a documented minimum client build of Windows 10 19041. The getter must receive only `Version`, with `Flags` initially zero. Both getter and [cleanup export](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-freeinterfacednssettings) are resolved before capture, and returned allocations are freed on success and serialization failure. The [settings structure](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-dns_interface_settings) exposes static adapter/profile nameserver fields. The structure's earlier availability does not establish earlier function availability.
- [LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw) with `LOAD_LIBRARY_SEARCH_SYSTEM32` restricts library lookup; [GetProcAddress](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getprocaddress) supports detecting missing optional exports. Older systems retain the rest of the snapshot and explicitly report this section unavailable.
- Native DNS read/reset semantics, policy/VPN precedence, and IPv4/IPv6 behavior still require controlled validation before enabling a restore setter. No networking setter was called during this research.

## Dedicated service constraints

- [Named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) warns that default ACLs include broad readers and that generic write grants create-pipe-instance. The implemented DACL uses specific client rights; live tests verify permitted data access and denied server-instance creation.
- [Pipe impersonation](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient) requires checking success before using the client identity. [RevertToSelf](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-reverttoself) requires terminating the process if reversion fails. Identification and reversion are synchronous and cannot span an async suspension.
- [LocalService](https://learn.microsoft.com/en-us/windows/win32/services/localservice-account) is a low-privilege built-in account without a password. It is sufficient for the current status-only protocol; network write privileges have not been granted. The [windows-service implementation](https://github.com/mullvad/windows-service-rs) supplies SCM lifecycle wrappers; its selected MIT/Apache-2.0 license permits use in this MIT project.
- The resolved Mio version reproduces the [stale read state on pipe reuse](https://github.com/tokio-rs/mio/issues/1983) report. The server uses fresh handles and keeps a listener alive, following [Tokio's named-pipe lifecycle pattern](https://docs.rs/tokio/1.54.1/tokio/net/windows/named_pipe/struct.NamedPipeServer.html), rather than recycling disconnected handles.
